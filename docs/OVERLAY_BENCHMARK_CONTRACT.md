# 覆盖基准行为合约 v4

付费覆盖 fixture 验证支持的行为,比较功效单独报告为研究证据。通过的用例**不**建立边际覆盖益处或资源非回归。这取代了以前的阻塞功效合约;历史失败保留其原始 verdict。

合约由 `test/helpers/overlay-case-policy.ts` 中的 `OVERLAY_CONTRACT` 定义。每个新的测量和聚合记录都标识版本 4。Eval 条目名称包括 `contract-v4`,因此自动化结果匹配不能静默地按相同名称比较旧合约和新合约。六个保留的付费用例的选择 ID 保持不变。

## 阻塞检查

两个臂都使用真实的 Claude Code 预设;ON 附加解析的覆盖,OFF 不附加。每个保留的 fixture 对 `claude-opus-4-7` 和 `claude-sonnet-4-6` 分别运行每个臂 10 个样本。每个 model 保留其自己的结果。

两个臂中的每个计划样本必须成功执行,产生恰好一个没有错误标志的成功原生终端结果,保留工作区范围,并在 fixture 的范围内产生有限指标。缺少推理元数据、oracle 进程错误、部分采样、截止日期、清理失败或录制失败会使用例失败。缺少的观察永远不会被替换为零或被丢弃以获得通过的臂。

一个失败的 fixture 输出检查的已完成答案是测量的正确性结果,而不是无效的测量,在任一臂中:其记录具有 `measurementPassed: true`、`taskCorrect: false` 以及检查的消息位于 `answerError`。只有 ON 正确性决定用例,因此 OFF 错误答案保留在比较中,而 ON 错误答案会使用例失败。版本 3 将 OFF 错误答案计为无效测量(census 37198445662);v3 verdict 不会被重新解释。

| Fixture 系列 | 确切的任务和范围合约 | 附加 ON 要求 | 测量 |
| --- | --- | --- | --- |
| `claude-dedicated-tools-vs-bash` | 只读工作区;原生最终 JSON 将所有五个 `src/` 路径映射到它们精确的导出符号名称 | 每个 ON 样本中的正确输出,以及比 OFF 少至少 20% 的 Bash 调用(当 OFF 中位数为 0 时,每个 ON 样本中 Bash 为零) | 总 Bash 工具调用 |
| `opus-4-7-effort-match-trivial` | 只读工作区;原生最终 JSON 包含确切的版本字符串 | 每个 ON 样本中的正确答案 | 原生 `usage.output_tokens_details.thinking_tokens` |
| `opus-4-7-literal-interpretation` | 仅 `src/auth.ts`、`src/billing.ts` 和 `src/notifications.ts` 可能更改;公共测试保持冻结;独立的行为检查在可写 fixture 之外运行 | 每个 ON 样本中的所有三个目标行为都通过 | 正确的目标行为,0..3 |

每个系列还有一个 `-sonnet` 用例。输出验证检查原生最终答案,因此前面提到的正确单词不能掩盖错误的最终答案。只读提示明确请求 JSON 形状。这些确切的答案提示是 v2 中的新内容:在同一合约和 fixture 内比较 ON/OFF,而不是跨版本比较。特别是,永远不要将当前的字面正确性度量与历史编辑文件计数进行比较。

OFF 字面样本可以有效地完成 0..3 个行为;这是测量的对照变量。OFF 专用工具样本可以有效地使用 Bash。ON 必须满足上述确切要求,即使其比较显示大幅改进;对于专用工具用例,20% 的 Bash 比较本身就是 gate 的一部分。范围在实现 oracle 之后再次检查,因为导入已修复的模块本身可以更改文件。每个 oracle 必须在断言之后发出其唯一的完成标记;在导入期间退出的实现不能伪装为通过的行为。

## 比较研究结果

原始数字比较器保持不变:至少少 20% 的 Bash 调用或报告的推理 token,以及至少多 20% 的正确字面目标。它们的 `criterionMet` 值、均值和原始每臂指标保留在聚合工件中。它们不决定 v2 行为 verdict。

| 比较状态 | 含义 |
| --- | --- |
| `improved` | 满足原始数字标准 |
| `baseline_saturated` | 每个 OFF 样本都达到了指标的最佳状态;没有证明的边际益处 |
| `no_measured_improvement` | 完整的测量未满足原始标准 |
| `regressed` | ON 的均值在指标的声明方向上更差 |
| `unsupported_hypothesis` | 解析的覆盖不包含所声称的干预 |
| `incomplete` | 缺少或无效的测量;行为用例也失败 |

最佳状态下的相等性是 `criterionMet: false` 的行为成功,而不是百分比改进。努力用例可以在其测量的推理 token 比较是 `regressed` 的同时通过正确性;该回归仍然可见。该产品要求 model 匹配努力与复杂性,并且不承诺普遍的 20% token 减少。此合约中没有校准的资源上限、非劣效边距或有效的采样方案。任何未来的资源回归 gate 都需要在收集新结果之前达成一致的实用边距、基线分布、采样设计和决策规则。

## 退役的 fanout 用例

当前解析的 `model-overlays/opus-4-7.md` 及其继承的 `claude.md` 不包含 fanout 指令。付费用例 `opus-4-7-fanout-toy`、`opus-4-7-fanout-realistic` 及其 `-sonnet` 变体已退役,包括它们的付费包装器和选择条目。它们不是重命名的成功。重新引入付费批处理功效实验需要实际的产品声明和区分实验。

免费回归保留原生第一消息片段分组、工具 ID 去重和原始 fanout 比较器。此度量衡量消息批处理,不能建立时钟执行并发性。

## 证据和执行

运行目录和 Bun/原生尝试标识保持唯一。工件文件使用独占创建;重试尝试无法覆盖先前的原始流、测量记录、工作区快照或聚合 verdict。在产生原生事件之前保存原生事件,包括后来抛出的流。经过验证的测量记录一次;单独的聚合以零额外成本和时间记录用例 verdict。失败的写入保留部分证据并使用例失败。版本控制永远不会重写历史工件。

付费 runner 为每个分片执行一个覆盖包装器,一次一个包装器,禁用 Bun 重试,并保留原生速率限制重试证据。在最终确定时,workers 必须在工作区清理开始之前结算。两者共享现有的五秒宽限期;到期会使用例失败并阻止延迟 workers 开始清理。每个 fixture 保留其原始回合上限、并发性、30 分钟工作预算和录制宽限期。六个包装器仍然是周期性用例;免费测试在没有进行 model 调用的情况下测试确定性结果。免费通过验证仪器,而不是实时 model 行为或积极的功效声明。
