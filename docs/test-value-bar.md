# 测试值栏

gstack 的测试工作流共享一条规则:测试通过保护真实回归会破坏的行为来赢得其位置。测试数量不是目标。该栏嵌入在 `/plan-eng-review`、`/review`、`/qa`、`/qa-only` 和 `/ship` 中,因此 diff 中的每个新测试或更改的测试都无需单独的步骤即可满足它。`/test-audit` 将同一栏应用于已存在的测试。

真实来源是 `scripts/resolvers/test-value.ts`。它改编自 OpenClaw 的 `test-audit` skill(openclaw/openclaw@a214e76,`.agents/skills/test-audit/SKILL.md`),并通用于任何测试运行程序。

## 词汇表

- **编写 gate**:每个新测试或更改的测试必须回答的四个问题。它保护什么行为、不变量或合约?什么可信的回归会导致它失败?为什么现有覆盖不能已经捕获到?它需要一个生产调用者不需要的生产 seam 吗?缺少答案意味着扩展现有测试或放弃该提案。
- **值栏**:编写 gate 加上规则:在保留行为的重构下中断的测试断言实现,除非其确切输出是声明的合约(黄金、提示字节、线格式)。
- **Prompt-byte 合约**:提示中的机器读取的 token,不能更宽。当软件使用其确切字节时,token 才合格:解析器、hook 或评分器匹配的标记或 sentinel 行;脚本读取的字段名称或 JSON 形状;代理运行的命令行、标志或环境变量;调用者分支的枚举值或状态词;另一个步骤打开的文件路径或占位符;或安全边界输入到模型中的确切字符串。英语句子不是 prompt-byte 合约,因为模型读取它:改写它不能中断测试。仅当记录的评估显示确切措辞更改行为时,才固定句子,并在 pin 旁边引用该评估。
- **句子 pin**:针对 SKILL.md、`.tmpl` 模板或 section 文件断言英语句子或子句(40 或更多字符的散文,或散文正则表达式)的测试。将其转换为结构检查(部分或标题存在,步骤保持其顺序,机器读取的 token 存在于正确的部分),或在行为评估已覆盖该行为时删除它,并在提交中命名该评估。在正确的部分对含义检查安全行(不区分大小写的关键字),而不是大写或强调。
- **保留栏**:保留独立执行公共 API、协议、配置、迁移、存储、安全、平台、默认、prompt-byte(如上定义)、生成输出(SKILL.md 黄金)、包、发布或架构合约的测试;当顺序可观察时调用顺序;当它是最低成本的独立保护时的源代码检查。静态或缓慢不是删除的理由。可从包入口点到达的任何内容都不会被弃用。
- **值卡**:gate 的四个答案作为一行,`Value: protects=<...>; fails_when=<...>; why_new=<...>; seam=none`。每个字段在该行中最多 160 个 UTF-8 字节(限制为 157 个字节加上 `...`);JSON 保留完整值,标题注释换行而不是截断。
- **弃用卡**:删除所需的证据,在任何编辑之前完成:`test`、`detects`、`non_test_callers`、`search_command`、`stronger_proof`、`history`、`unlocks`、`validation`。
- **弱路径**:更改的路径,其唯一测试是弱的:★ 测试(烟雾、存在、平凡断言)、失败的 gate 的新测试,或在此 `/ship` 运行中编写的未经评分传递的测试。原因:`star_one | gate_failed | unrated`。
- **X 和 Y**:X = 具有 ★★ 或 ★★★ 测试的路径 / 总路径(值加权;`/ship` gate 使用 X)。Y = 具有任何测试的路径 / 总路径。总路径是 diff 的代码路径跟踪,上限为 30;零路径跳过 gate。
- **基本控制**:针对基本分支在临时 worktree 中运行新的回归测试,以证明行为存在且测试有效。
- **Grep-only**:来自文本搜索的调用者证据。它看不到重新导出、动态分派或生成的代码,因此生产代码永远不会仅根据 grep 证据删除。

## 工作的 X/Y 示例

diff 触及 10 个路径。其中四个具有 ★★ 或 ★★★ 测试,三个仅具有 ★ 烟雾测试,三个没有测试。

- X = 4 / 10 = 40% 值加权。Gate 使用此数字。
- Y = 7 / 10 = 70% 包括弱覆盖的路径。
- `gaps` = 3(无测试);`weak_gaps` = 3 个 ★ 唯一路径,原因为 `star_one`。

PR 主体显示 `Coverage: 40% value-weighted (70% including 3 weakly covered paths)`。

## 卡

一个好的值卡:

```text
Value: protects=refundPayment rejects an empty reason; fails_when=the reason guard is removed or inverted; why_new=billing.test.ts covers processPayment only; seam=none
```

被拒绝的提案:

```text
Rejected (covered_elsewhere): "checkout renders"; checkout.e2e.ts:15 covers it, so extend that test.
```

拒绝代码:`duplicate_protects`、`needs_seam`、`incomplete_card`、`no_credible_regression`、`covered_elsewhere`、`implementation_coupled`。

## 由 `/ship` 编写的标题注释

TypeScript:

```ts
// Generated by /ship coverage audit
// Value: protects=refundPayment rejects an empty reason;
//   fails_when=the reason guard is removed or inverted;
//   why_new=billing.test.ts covers processPayment only; seam=none
test('refundPayment rejects an empty reason', () => {
  expect(() => refundPayment('pay_1', '')).toThrow('Reason required');
});
```

Python:

```python
# Generated by /ship coverage audit
# Value: protects=refund rejects an empty reason;
#   fails_when=the reason guard is removed or inverted;
#   why_new=test_billing.py covers process_payment only; seam=none
def test_refund_rejects_empty_reason():
    with pytest.raises(ValueError, match="Reason required"):
        refund_payment("pay_1", "")
```

没有已知注释语法的文件类型在 PR 主体的 Test value 详细信息中获取其卡。

## 覆盖

项目在 `CLAUDE.md` `## Test Coverage` 部分中调整 `/ship`。每个键都是可选的;缺失的键使用默认值。

```markdown
## Test Coverage
Minimum: 60%
Target: 80%
Generation cap: 5
Base control: auto
Base control budget: 90
Star rating: auto
```

- `Generation cap:` 每次生成传递的测试(默认 5;最多 2 次传递)。
- `Base control:` `auto` 在基本分支上运行回归测试;`off` 跳过它。
- `Base control budget:` 每次基本控制运行的秒数(默认 90;总共 3 分钟)。
- `Star rating:` `off` 使 gate 使用 `coverage_pct`(任何测试);弱路径仍然列出。

每个测试的 pragma,在文件的注释语法中,使 `/review` 和 `/test-audit` 跳过故意的测试并报告原因:

```ts
// gstack:test-value keep reason="pins the v1 wire format for external clients"
```

## 消息

每个降级模式消息都命名问题、其后果和修复。

### rating-unavailable

`rating unavailable`:只读评分派发失败或超时,因此本次运行跳过覆盖率 gate。重新运行 `/ship` 的 Step 7 以重新评分测试。

### value-weighted-coverage-unavailable

覆盖率审计未返回可用的 `coverage_pct_value`,通常是因为已安装的 skill 早于此更改。Gate 在本次运行中使用 `coverage_pct`(任何测试)。运行 `/gstack-upgrade`。

### inconsistent-coverage-inputs

`coverage_pct_value` 高于 `coverage_pct`,当两者都从同一路径计算时,这不会发生。它被限制为 `coverage_pct`。如果数字看起来错误,请重新运行 Step 7。

### malformed-key-ignored

Step 7 JSON 键的类型错误(例如 `weak_gaps` 不是数组),因此它计为空。可能的原因是已安装的 skill 过时;运行 `/gstack-upgrade`。

### all-generated-tests-rejected

生成传递中编写的每个测试都未能通过机器检查(不完整的卡、重复的 `protects` 或没有非测试调用者的 seam)。被拒绝的文件已删除,gate 继续使用未更改的值加权覆盖率。有关每个原因,请参见 `tests_rejected`。

### base-control-unavailable

回归测试无法在基本分支上运行:`ecosystem`(不是 Node/Bun 项目)、`no base remote`、`base not fetched`、`worktree add failed`、`budget`,或 `collection error`(测试无法在基本加载)。fails-at-HEAD 结果仍然有效。要手动检查:

```bash
git worktree add --detach /tmp/base-check origin/<base>
cp <test> /tmp/base-check/<test>          # plus any new test-only fixtures
(cd /tmp/base-check && <test command for that file>)
git worktree remove --force /tmp/base-check
```

然后报告 `passes at base: manual`。

### caller-check-unavailable

非测试调用者搜索失败,或符号不是普通标识符(`unsupported symbol`)。发现保留为 INFORMATIONAL,不提出删除。要完成证据,请手动运行搜索。

### unknown-test-value-bar-mode

模板使用 `{{TEST_VALUE_BAR:<mode>}}` 时使用的模式不是 `plan|ship|qa|audit`。修复占位符或在 `scripts/resolvers/test-value.ts` 中添加模式。
